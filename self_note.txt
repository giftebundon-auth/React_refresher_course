Summary from Video 74
1. State is internal data. Data owned by the component in which it is declared
2 props is external data, data that is owned by the parent component
3. props similar to function parameters
4. State known as the component memory, can be updated by the component itself
5. Updating state causes component to re-render. This mechanism makes component interactive
6. props are read-only
7. Receiving new props causes component to re-render. Usually when parent's state has been updated, the child component then receives it as a new/updated props
8. In conclusion, whenever a piece of state is passed as a prop, both the parent and child components re-renders
9. States are used to make component interactive while props are used by parent component to configure child component


Summary from video 79 (State management)
State management is deciding when we need to create new piece of state, what type of state we need, where to place each piece of state inside our codebase and also how all the data should flow through the app. 
In summary, state management is basically giving each piece of state a home within our codebase



=> In react, each piece of state is either a global or local state.
=> Local state is a state needed by one or few components
=> Local state is a state that is defined in a component and only that component and child components have access to it (by passing via props)
=> Global State is a state that many component might need
=> Global state is a shared state that is accessible to every component in the entire application
=> Global state can be defined using React Context API or an external global  state management library like REDUX
